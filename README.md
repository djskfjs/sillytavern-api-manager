# SillyTavern API 账户管理器

一个面向 **SillyTavern 1.14.x** 的轻量第三方扩展，用来集中管理多个 API 账户和模型。它不需要构建步骤，仓库内容可以直接放入酒馆的第三方扩展目录。

当前版本：**1.8.24**

## 功能

- 填写 API 地址和 Key，自动适配需要或不需要 `/v1` 的模型接口，选择默认模型。
- 模型查询兼容字符串列表、标准 `data`、`models` 及嵌套 `data` 格式；临时网关错误会尝试酒馆转发，酒馆网关错误自动重试一次。
- 常规模型查询失败时，自动尝试同站点 New API / One API 的公开模型目录。目录不使用 API Key，界面标注“公开目录”，其中模型是否可用取决于当前 Key 的分组和权限。
- 获取失败会保留已有模型；也可在编辑中填写“手动模型 ID”。已选择或手动填写模型时可以直接应用，无需先获取列表；未验证的基础地址默认补 `/v1`，显式版本路径和已验证的接口地址优先保留。应用成功只表示配置已填入酒馆。
- 分组栏可以点击已有分组或直接填写新分组；选中自定义分组后可重命名，组内账户和轮询范围同步更新。
- 账户列表顶部按“全部、收藏、自定义分组”排列，使用可换行的圆角气泡按钮，并记住当前筛选；“全部”视图中已收藏账户优先排列，分组内收藏或取消收藏均保留原来的排序位置。
- “定位”图标浮动在回顶图标上方，与回顶使用相同的圆形、主题强调色和 1.5px 细线；在当前分组或收藏视图内查找已应用站点，站点不在当前范围时显示提示，保留当前分组和搜索条件。
- 回顶按钮使用主题强调色和 1.5px 细线图标，位于扩展右侧偏下；下滑看到当前列表第 2 个站点的完整内容时显示，无需等前两张卡片滚出屏幕顶部，回到顶部或关闭扩展后隐藏。
- 从聊天页重新打开插头面板时恢复上次浏览位置，保留分组、搜索条件和当前编辑页面；点击“定位”图标时才跳到已应用的站点。
- “我的账户”下方可选择按名字或按添加顺序的升序、降序，并记住选择；名字按中文拼音、英文和数字自然排序，添加顺序升序为先添加在前，降序为后添加在前。排序适用于当前分组和搜索结果，分组内不受收藏状态影响。
- 删除站点后保留当前面板的滚动位置；删除靠近底部的站点时，随剩余内容高度自然调整，方便继续管理相邻站点。
- 输入站点名称即可实时筛选，支持部分名称和不区分大小写的匹配；在分组或收藏视图中只搜索该范围，清空搜索恢复列表。
- “应用”会同时把账户标记为当前账户；开启轮询后，当前 API 正常时一直使用，生成请求报错后才切换到同一分组或收藏范围内的下一个 API。
- 每个站点卡片都有“停止轮询 / 恢复轮询”按钮；已停止的站点显示“已跳过”，不会被轮询选中，设置会保存并同时作用于分组和收藏范围。
- 根据 API 地址识别账户余额接口；支持通过网站账户访问令牌查询 New API / One API 中转站的账户余额。
- 添加或编辑 API 时，填写网站账户访问令牌和用户 ID 后保存，会自动查询并显示余额；修改这些查询信息也会自动重新查询。
- “我的账户”旁的“刷新余额”会立即显示进度，优先刷新当前列表；同时最多查询三个站点，完成后提示成功与失败数量。
- 点击账户的“应用”会填入原生连接信息并自动连接，保留当前滚动位置；可按间隔自动刷新余额。
- API Key 不显示在账户列表中；编辑时自动填入已保存的 Key，默认用圆点遮盖，点击“显示”可查看。清空后需要填写有效 Key 才能保存。
- 支持系统令牌“加密同步保存”：浏览器使用独立密码加密，酒馆配置只保存密文。工具栏可一键迁移当前能读取的旧令牌，跨设备用同一密码解锁；刷新或闲置 15 分钟后自动锁定。
- 账户管理以可展开、收起的卡片显示在酒馆 **聊天补全 → 自定义（OpenAI 兼容）→ 可用模型** 后面，适配侧栏宽度。
- “我的账户”和“添加 API”可分别展开、收起，标题使用统一的小矩形标记；收起账户区会保留搜索条件和编辑草稿。
- 每个站点卡片都可直接获取模型并在当前下拉框中切换，更新列表时保留已有默认模型。
- 点击“编辑”在当前站点卡片内修改，保存或取消后收起；添加 API 保留独立表单，余额在账户旁直接查询、显示。
- 编辑当前站点后直接保存会保留原模型和“当前”标记，即使最新模型列表不包含原模型，也不会自动换成其他模型。
- 保存或取消编辑后回到刚编辑站点原先的屏幕位置；改名导致排序变化时仍跟随该站点。若新名称不再匹配搜索词，会清空搜索以显示该站点。
- 未填写系统令牌的站点隐藏余额、余额错误、更新时间及刷新余额按钮，也不参与余额刷新；所有站点都未填写令牌时，顶部刷新余额和自动刷新设置一并隐藏。填入令牌后恢复显示。
- 文字、背景和按钮使用酒馆的主题颜色，切换主题即时生效；用留白和浅底色区分区域，减少边框和分隔线。
- 当前账户带强调底色和徽标，“应用”作为主操作；轮询仅在具体分组和收藏视图中显示，开关对应当前查看的范围。
- 操作结果只通过弹窗提示。应用完成后弹出包含账户名和模型名的成功提示；切换中的进度显示在按钮上，轮询切换后提醒重新生成，提示会一直保留到玩家点击关闭。

## 安装

### 从 GitHub 安装（推荐）

1. 在 SillyTavern 打开 **扩展 → 安装扩展**。
2. 在 Git URL 输入框粘贴本仓库地址：

   ```text
   https://github.com/djskfjs/sillytavern-api-manager
   ```

3. 分支或标签输入框留空，点击 **Install just for me（仅为我安装）**。只有需要给所有用户安装时，才选择 **Install for all users**。
4. 安装完成后重新加载页面，点击顶部 **插头图标（API 连接）**，选择 **聊天补全 → 自定义（OpenAI 兼容）**，在“可用模型”后面点击 **API 账户管理** 卡片展开。

仓库根目录已包含扩展清单和运行文件，无需下载 ZIP、编译或手动复制文件。后续可在酒馆的扩展管理中检查更新。

### 手动安装

如果不使用安装器，将本仓库文件夹复制到当前用户的扩展目录（1.14.0 默认是 `data/<用户>/extensions/`）：

```text
SillyTavern/data/default-user/extensions/sillytavern-api-manager/
```

多用户部署时把 `default-user` 换成实际用户目录名。管理员要安装为所有用户时，才使用酒馆的全局第三方扩展目录 `public/scripts/extensions/third-party/`。目录中应至少包含 `manifest.json`、`index.js`、`api-routing.js`、`balance.js`、`generation-monitor.js`、`token-storage.js`、`token-vault.js`、`credential-security.js`、`settings.html` 和 `style.css`。然后重启酒馆。

## 使用

1. 打开顶部 **插头图标 → 聊天补全 → 自定义（OpenAI 兼容）**，点击“可用模型”后面的 **API 账户管理** 面板展开。顶部依次为全部、收藏和自定义分组；选中自定义分组后点击“重命名”。在“添加 API”中填写账户名称，并选择已有分组或输入新分组。
2. 直接填写 API 基础地址和 Key，点击“获取模型”并选择默认模型，然后点击“保存 API”。地址末尾的 `/v1` 由扩展处理，不需要手动选择。
3. 点击账户的“应用”会将其设为当前账户并高亮显示，同时填写连接信息并发起连接。按钮在处理期间显示“切换中…”，完成后弹窗显示“切换成功：账户名 · 模型名”。成功提示确认配置已应用；自定义接口可能跳过连接检查，实际可用性以生成结果为准。点击右上角的 ☆ 可收藏；在分组内保留原位置，在“全部”视图中优先显示。分组轮询顺序也不受收藏或取消收藏影响。
4. 填好网站账户访问令牌和用户 ID 后保存，余额会自动查询并显示在站点卡片上；已有正常余额且查询信息未改变时保留结果。也可点击单个账户的“刷新余额”，或使用“我的账户”旁的按钮刷新全部余额；批量刷新会显示完成进度和成功、失败数量。编辑账户时也能在表单内查询，查询不会清空尚未保存的名称或分组。
5. 已有站点可以在卡片上直接“获取模型”；点击“编辑”就在当前卡片内填写、选择模型并保存，或取消退出。下方“添加 API”表单用于新增站点，可以单独折叠。
6. 选择至少包含两个参与轮询账户的分组或收藏视图，在分组按钮下方找到轮询设置；“全部”首页不显示此设置。先“应用”组内一个参与轮询的 API，再点击“开启轮询”。扩展会锁定该范围，正常请求和空闲等待都不会换站；当前 API 的聊天请求报错后，才按轮询顺序应用范围内的下一个 API，并提示重新生成。列表排序只用于显示；切换列表视图不会改变已开启的范围，在其他分组中开启会将范围改到该分组。手动应用范围外的 API 时暂停切换，回到范围内恢复。
7. 在不想参与轮询的站点卡片上点击“停止轮询”，以后自动切换会跳过它；点击“恢复轮询”可重新加入。轮询开启前或运行中都能调整，刷新页面、编辑账户或更改分组后仍会保留。停止当前正在使用的站点不会立即换站，自动切换会暂停；应用其他参与轮询的站点后恢复。参与账户不足两个时会关闭该范围的轮询，恢复足够的账户后需要重新点击“开启轮询”。

轮询在收到 HTTP 错误、JSON 错误响应或流式错误时切换；发送请求时网络断开或读取响应流时连接中断不会触发切换。手动停止生成、余额查询、模型列表查询及后台静默生成不会触发切换。切换不会自动重发消息；切换提示会一直显示，直到点击提示或关闭按钮，之后请点击重新生成。升级后旧的轮询分钟数和轮询游标会被移除，已开启的有效分组或收藏范围会保留。

卡片默认收起，点击标题栏即可展开或收起内容。内部的“我的账户”和“添加 API”也可以分别折叠，展开和收起不会清空搜索条件或正在填写的表单。

从旧版本更新后，请刷新页面，在“可用模型”后面找到卡片。已有账户、Key、模型和分组会保留。由于旧版无法区分“仅选中”和“已经应用”，升级到 1.7.0 后请重新点击一次“应用”建立当前账户标识。修改默认模型时点击“编辑”。

## 余额接口说明

扩展只显示可确认的站点账户余额，不查询或回退显示聊天 API Key 的可用额度、限额或无限额度标记。

“自动识别账户余额接口”支持 DeepSeek、OpenRouter、硅基流动、Moonshot，以及明确声明返回账户余额的同站点接口。OpenAI 官方普通 API Key 没有账户余额接口，查询失败不会显示为余额为零。

**站点余额查询** 直接展开在添加和编辑 API 共用的表单中，使用与上方填写项相同的标签和控件样式。新增 API 默认选择 **网站账户（中转站）**，保存或取消编辑后，新建表单也会恢复此默认值；已有账户沿用保存的查询方式。对于 New API / One API 中转站，填写网站个人设置中的账户访问令牌和用户 ID，然后保存，扩展会自动查询余额；修改令牌、用户 ID 或站点地址后保存也会重新查询。查询失败时保留已保存的 API，并在卡片上显示具体原因。需要时也可手动选择 **自动识别账户余额接口**。访问令牌与聊天 API Key 是两种不同的凭据；New API 通常要求用户 ID，部分旧 One API 站点可留空。

网站账户模式读取同一站点的 `/api/user/self`，优先使用明确的剩余总额度 `total_quota`；没有总额时，使用 `quota`，若接口同时提供 `gift_quota`，则将充值余额与赠送余额相加。已有总额时不会重复加赠送额度，也不会再次扣除历史用量或把历史充值额当作余额。哈基米等使用相同字段的站点均按此规则处理。

金额按照 `/api/status` 公布的币种、单位和汇率换算，支持 USD、CNY、自定义单位（例如 Aether API 的 `Payload`）及原始额度。站点未公开完整换算信息时，显示原始的账户额度单位。自动识别接口也优先采用明确的账户总额；无法确认总额时显示查询失败，避免把部分余额当成总余额。网站账户接口与 API 分属不同域名的站点，当前需要提供同域的账户查询接口。

编辑时将账户访问令牌留空可保留已保存的值，也可勾选“清除已保存的账户访问令牌”后保存。账户令牌仅用于余额查询，不会填入聊天连接或发送到其他域名。查询错误会隐藏凭据。

### 模型查询与酒馆登录

模型查询先直接请求 API；遇到跨域或网络限制时，使用当前酒馆的原生模型查询接口。API Key 通过请求正文单独交给酒馆，避免覆盖酒馆自己的 HTTP 登录认证。获取模型不会修改酒馆当前保存的 Key 或启动聊天连接，也无需开启 CORS 代理。

### 跨域查询

通过 localhost、127.x.x.x 或 [::1] 回环地址访问的本地酒馆，余额直接由本机酒馆后台查询，不先尝试浏览器直查、不弹转发确认，自动刷新也使用本机后台。系统令牌选择“仅此浏览器保存”或“随酒馆同步保存”都可以查询，保存位置不决定查询方式。

通过其他地址访问时（包括域名和局域网地址），余额默认由浏览器直查。手动查询遇到跨域、网络或临时网关错误时，会询问是否允许当前酒馆服务器仅为本次查询转发；确认前不发送转发请求，取消则停止。批量刷新最多询问一次，授权只覆盖这次批量刷新中直查失败的站点，不保存为长期权限。旧的自动转发许可不再使用。

非回环地址下，后台自动刷新只做浏览器直查，不弹确认框、不通过酒馆转发。认证失败、权限不足或限流直接显示错误，不通过转发反复尝试。酒馆查询通道遇到 HTTP 502、503、504 时最多重试一次，并沿用当前酒馆登录状态，无需开启通用 CORS 代理。

站点仍须提供账户余额接口和相应查询权限；仅开放聊天密钥额度的接口不能代替账户余额。

## 安全与隐私

“余额查询（可选）”在未配置令牌时默认折叠；只管理 API 和模型无需展开。保存方式和加密操作收在其中的“高级：令牌保存方式”，已有账户沿用原设置，改名或升级不会自动迁移。新增账户默认“随酒馆同步保存”，将未加密的系统令牌随酒馆配置保存，供其他设备使用；也可主动选择“仅此浏览器保存”，换设备、浏览器、酒馆域名或清除网站数据后需补填。

“加密同步保存”使用浏览器 Web Crypto 的 AES-256-GCM 加密系统令牌，PBKDF2-SHA-256（600,000 次迭代）从独立密码派生不可导出的会话密钥，使用随机盐和每条密文独立的随机 IV，并把密文绑定到站点地址和账户标识。密码和解密后的系统令牌不会保存到酒馆配置；其他设备读取密文后，在当前浏览器输入同一密码解锁。需使用支持 Web Crypto 与 dialog 的现代浏览器，以及 HTTPS 或本机回环地址。

在编辑页展开“余额查询（可选）→高级：令牌保存方式”，点击“加密令牌”，设置至少 12 个字符的独立密码，可将当前能读取的系统令牌迁移为加密同步保存，无需重新填写。旧的浏览器明文副本会从扩展当前存储中移除，酒馆当前配置改存密文；旧备份不会自动清除。仅存在另一浏览器中的令牌需在原浏览器迁移。加密始终由用户主动选择，不会自动改变新增账户的保存方式。“加密其余令牌”可继续迁移尚未加密的账户。

迁移前会先在当前浏览器保存密文恢复副本（不含密码或聊天 API Key），写入失败则停止迁移。若酒馆同步失败，刷新后出现“恢复加密令牌”按钮，可将同站点的密文恢复到当前配置，再用原密码解锁；恢复不会自动覆盖用户操作。

刷新、关闭页面或闲置 15 分钟会锁定会话密钥。锁定时自动刷新跳过加密令牌；手动查询可以解锁，改名、排序等操作仍会保留密文。忘记密码无法恢复令牌；可在解锁窗口选择清除加密令牌后重设，站点资料、聊天 API Key 和其他保存方式的令牌保留。

本地回环地址访问时，查询凭据会直接交给本机酒馆后台；其他地址下，只有用户确认本次转发，查询凭据才会发送给当前酒馆服务器，其管理员或日志收集工具可能接触到它。“随酒馆同步保存”仍会把系统令牌存入酒馆配置，保存位置与查询途径是两回事。优先使用站点提供的独立、只读、可撤销的余额查询令牌。

聊天 API Key 仍随酒馆设置保存，原生聊天请求也通常经酒馆服务器发送；这项加密只保护系统令牌。“仅此浏览器保存”和“随酒馆同步保存”没有密码加密。加密同步保存保护的是存储文件，不阻止被控制的酒馆网页窃取输入的密码或查询时的令牌；用户允许云端转发后，服务器仍会接触查询令牌。此前已经上传过的令牌若担心旧备份泄露，应在站点撤销并重新生成。

获取模型、保存/导入、应用站点以及未加密系统令牌的保存和余额查询兼容 HTTP 云酒馆。只有可选的加密与解锁要求酒馆使用 HTTPS 或本机回环地址；不支持时高级设置显示原因，并保留已有密文。带凭据的 API 目标仍要求 HTTPS，localhost、127.0.0.1 等本机回环地址除外。HTTP 酒馆到浏览器之间没有 TLS 传输加密。余额查询限制在填写站点的同一来源，浏览器请求禁止重定向，报错会隐藏凭据。扩展不会把凭据发送给扩展作者或 GitHub。

API Key 编辑时自动填入并默认遮盖，点击“显示”可查看；网站系统令牌编辑时仍不回显，留空可保留原令牌。当前导出的 API 配置不包含网站系统令牌，但包含聊天 API Key，请勿公开分享。删除账户会清除扩展当前保存的凭据，不会清除酒馆历史备份；曾经上传的令牌若需要彻底失效，应在站点撤销重建。

## 兼容性

- 目标版本：SillyTavern 1.14.0 及相近 1.14.x 版本。
- 模型获取协议：OpenAI 兼容 `GET <baseUrl>/models`，自动尝试同一站点带或不带 `/v1` 的地址，保留路径前缀；支持 `{ data: [{ id }] }`、`{ models: [...] }` 等模型列表格式。
- “应用”按钮使用酒馆 1.14.x 的原生自定义聊天补全控件；余额查询和分组编辑不打开新窗口或独立页面。

## 开发

这是无构建依赖的 ES module 扩展。修改后把仓库目录放回 `public/scripts/extensions/third-party/`，刷新页面即可验证。提交前建议运行：

```bash
node --check index.js
node --check balance.js
node --check api-routing.js
node --check generation-monitor.js
node --check token-storage.js
node --check token-vault.js
node --check credential-security.js
```
