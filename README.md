# SillyTavern API 账户管理器

一个面向 **SillyTavern 1.14.x** 的轻量第三方扩展，用来集中管理多个 API 账户和模型。它不需要构建步骤，仓库内容可以直接放入酒馆的第三方扩展目录。

当前版本：**1.8.4**

## 功能

- 填写 API 地址和 Key，自动适配需要或不需要 `/v1` 的模型接口，选择默认模型。
- 分组栏可以点击已有分组或直接填写新分组；选中自定义分组后可重命名，组内账户和故障切换范围同步更新。
- 账户列表顶部按“全部、收藏、自定义分组”排列，使用可换行的圆角气泡按钮，并记住当前筛选；已收藏账户在列表中优先排列。
- 输入站点名称即可实时筛选，支持部分名称和不区分大小写的匹配；在分组或收藏视图中只搜索该范围，清空搜索恢复列表。
- “应用”会同时把账户标记为当前账户；开启故障切换后，当前 API 正常时一直使用，生成请求报错后才切换到同一分组或收藏范围内的下一个 API。
- 根据 API 地址识别账户余额接口；支持通过网站账户访问令牌查询 New API / One API 中转站的账户余额。
- 点击账户的“应用”会填入原生连接信息并自动连接，保留当前滚动位置；可按间隔自动刷新余额。
- API Key 默认不回显到列表，编辑时将输入框留空即可保留原 Key。
- 账户管理以可展开、收起的卡片显示在酒馆 **聊天补全 → 自定义（OpenAI 兼容）→ 可用模型** 后面，适配侧栏宽度。
- “我的账户”和“添加 API”可分别展开、收起，标题使用统一的小矩形标记；收起账户区会保留搜索条件和编辑草稿。
- 每个站点卡片都可直接获取模型，更新该站点的模型列表并保留已有默认模型。
- 点击“编辑”在当前站点卡片内修改，保存或取消后收起；添加 API 保留独立表单，余额在账户旁直接查询、显示。
- 文字、背景和按钮使用酒馆的主题颜色，切换主题即时生效；用留白和浅底色区分区域，减少边框和分隔线。
- 当前账户带强调底色和徽标，“应用”作为主操作；故障切换仅在具体分组和收藏视图中显示，开关对应当前查看的范围。
- 操作结果只通过弹窗提示。应用完成后弹出包含账户名和模型名的成功提示；切换中的进度显示在按钮上，故障切换完成后提醒重新生成。

## 安装

### 从 GitHub 安装（推荐）

1. 在 SillyTavern 打开 **扩展 → 安装扩展**。
2. 在 Git URL 输入框粘贴本仓库地址：

   ```text
   https://github.com/djskfjs/sillytavern-api-manager
   ```

3. 分支或标签输入框留空，点击 **Install just for me（仅为我安装）**。只有需要给所有用户安装时，才选择 **Install for all users**。
4. 安装完成后重新加载页面，点击顶部 **插头图标（API 连接）**，选择 **聊天补全 → 自定义（OpenAI 兼容）**，在“可用模型”后面点击 **API 账户管理** 卡片展开。

仓库根目录已包含扩展清单和运行文件，无需下载 ZIP、编译或手动复制文件。后续可在酒馆的扩展管理中检查更新。

### 手动安装

如果不使用安装器，将本仓库文件夹复制到当前用户的扩展目录（1.14.0 默认是 `data/<用户>/extensions/`）：

```text
SillyTavern/data/default-user/extensions/sillytavern-api-manager/
```

多用户部署时把 `default-user` 换成实际用户目录名。管理员要安装为所有用户时，才使用酒馆的全局第三方扩展目录 `public/scripts/extensions/third-party/`。目录中应至少包含 `manifest.json`、`index.js`、`api-routing.js`、`balance.js`、`generation-monitor.js`、`settings.html` 和 `style.css`。然后重启酒馆。

## 使用

1. 打开顶部 **插头图标 → 聊天补全 → 自定义（OpenAI 兼容）**，点击“可用模型”后面的 **API 账户管理** 面板展开。顶部依次为全部、收藏和自定义分组；选中自定义分组后点击“重命名”。在“添加 API”中填写账户名称，并选择已有分组或输入新分组。
2. 直接填写 API 基础地址和 Key，点击“获取模型”并选择默认模型，然后点击“保存 API”。地址末尾的 `/v1` 由扩展处理，不需要手动选择。
3. 点击账户的“应用”会将其设为当前账户并高亮显示，同时填写连接信息并发起连接。按钮在处理期间显示“切换中…”，完成后弹窗显示“切换成功：账户名 · 模型名”。成功提示确认配置已应用；自定义接口可能跳过连接检查，实际可用性以生成结果为准。点击右上角的 ☆ 可收藏并置顶。
4. 点击账户旁的“刷新余额”，结果直接显示在该账户旁。编辑账户时也能在表单内查询，查询不会清空尚未保存的名称或分组。
5. 已有站点可以在卡片上直接“获取模型”；点击“编辑”就在当前卡片内填写、选择模型并保存，或取消退出。下方“添加 API”表单用于新增站点，可以单独折叠。
6. 选择至少包含两个账户的分组或收藏视图，在分组按钮下方找到故障切换设置；“全部”首页不显示此设置。先“应用”组内一个 API，再点击“开启故障切换”。扩展会锁定该范围，正常请求和空闲等待都不会换站；当前 API 的聊天请求报错后，才按列表顺序应用下一个 API，并提示重新生成。切换列表视图不会改变已开启的范围；在其他分组中开启会将范围改到该分组。手动应用范围外的 API 时暂停切换，回到范围内恢复。

故障切换覆盖 HTTP 错误、网络断开、JSON 错误响应和流式错误。手动停止生成、余额查询、模型列表查询及后台静默生成不会触发切换。切换不会自动重发消息；报错后请点击重新生成。升级后旧的轮询分钟数和轮询游标会被移除，已开启的有效分组或收藏范围会保留。

卡片默认收起，点击标题栏即可展开或收起内容。内部的“我的账户”和“添加 API”也可以分别折叠，展开和收起不会清空搜索条件或正在填写的表单。

从旧版本更新后，请刷新页面，在“可用模型”后面找到卡片。已有账户、Key、模型和分组会保留。由于旧版无法区分“仅选中”和“已经应用”，升级到 1.7.0 后请重新点击一次“应用”建立当前账户标识。修改默认模型时点击“编辑”。

## 余额接口说明

扩展只显示可确认的站点账户余额，不查询或回退显示聊天 API Key 的可用额度、限额或无限额度标记。

“自动识别账户余额接口”支持 DeepSeek、OpenRouter、硅基流动、Moonshot，以及明确声明返回账户余额的同站点接口。OpenAI 官方普通 API Key 没有账户余额接口，查询失败不会显示为余额为零。

对于需要网站账户认证的 New API / One API 中转站，编辑该 API，展开 **站点余额查询**，选择 **网站账户（中转站）**，填写网站个人设置中的账户访问令牌和用户 ID，然后保存。访问令牌与聊天 API Key 是两种不同的凭据；New API 通常要求用户 ID，部分旧 One API 站点可留空。

网站账户模式读取同一站点的 `/api/user/self`，使用账户的剩余额度，并按照 `/api/status` 公布的币种、单位和汇率换算；不会再次扣除历史用量。站点未公开完整换算信息时，显示原始的账户额度单位。网站账户接口与 API 分属不同域名的站点，当前需要提供同域的账户查询接口。

编辑时将账户访问令牌留空可保留已保存的值，也可勾选“清除已保存的账户访问令牌”后保存。账户令牌仅用于余额查询，不会填入聊天连接或发送到其他域名。查询错误会隐藏凭据。

### 模型查询与酒馆登录

模型查询先直接请求 API；遇到跨域或网络限制时，使用当前酒馆的原生模型查询接口。API Key 通过请求正文单独交给酒馆，避免覆盖酒馆自己的 HTTP 登录认证。获取模型不会修改酒馆当前保存的 Key 或启动聊天连接，也无需开启 CORS 代理。

### 跨域查询

余额接口允许浏览器跨域请求时会直接查询；遇到跨域或网络限制时，扩展会自动使用当前酒馆的后端请求通道，并沿用当前酒馆登录状态。无需开启通用 CORS 代理，也不会用站点 API Key 覆盖酒馆自身的 HTTP 访问认证。

站点仍须提供账户余额接口和相应查询权限；仅开放聊天密钥额度的接口不能代替账户余额。

## 安全与隐私

API Key 和可选的网站账户访问令牌会随 SillyTavern 的扩展设置保存在本机浏览器/服务器设置中，仅发送到该账户配置的同一站点。输入框默认隐藏凭据，编辑时不会回显已保存的值；扩展不会把凭据写入日志、账户列表或 GitHub。请不要把包含个人设置文件的目录提交到仓库，也不要把凭据写进预设或源码。删除账户会同时删除这些凭据。

## 兼容性

- 目标版本：SillyTavern 1.14.0 及相近 1.14.x 版本。
- 模型获取协议：OpenAI 兼容 `GET <baseUrl>/models`，自动尝试同一站点带或不带 `/v1` 的地址，保留路径前缀；支持 `{ data: [{ id }] }`、`{ models: [...] }` 等模型列表格式。
- “应用”按钮使用酒馆 1.14.x 的原生自定义聊天补全控件；余额查询和分组编辑不打开新窗口或独立页面。

## 开发

这是无构建依赖的 ES module 扩展。修改后把仓库目录放回 `public/scripts/extensions/third-party/`，刷新页面即可验证。提交前建议运行：

```bash
node --check index.js
node --check balance.js
node --check api-routing.js
node --check generation-monitor.js
```
