# SillyTavern API 账户管理器

一个面向 **SillyTavern 1.14.x** 的轻量第三方扩展，用来集中管理多个 API 账户和模型。它不需要构建步骤，仓库内容可以直接放入酒馆的第三方扩展目录。

## 功能

- 填写 API 地址和 Key，调用 OpenAI 兼容的 `GET /models` 获取模型并选择默认模型。
- 填写 API 时同时填写名称和分组；每个分组可独立展开、收起，并记住开合状态。
- 根据 API 地址自动识别余额接口，包括常见 New API 中转站；无需选择服务商或填写余额设置。
- 点击账户的“应用”会填入原生连接信息并自动连接；可按间隔自动刷新余额。
- API Key 默认不回显到列表，编辑时将输入框留空即可保留原 Key。
- 账户管理以可展开、收起的卡片显示在酒馆 **聊天补全 → 自定义（OpenAI 兼容）→ 可用模型** 后面，适配侧栏宽度。
- 添加 API 时同时填写分组；余额在账户旁直接查询、显示，所有操作都在同一面板完成。
- 文字、背景、边框和按钮使用酒馆的主题颜色，切换主题即时生效。

## 安装

### 从 GitHub 安装（推荐）

1. 在 SillyTavern 打开 **扩展 → 安装扩展**。
2. 在 Git URL 输入框粘贴本仓库地址：

   ```text
   https://github.com/djskfjs/sillytavern-api-manager
   ```

3. 分支或标签输入框留空，点击 **Install just for me（仅为我安装）**。只有需要给所有用户安装时，才选择 **Install for all users**。
4. 安装完成后重新加载页面，点击顶部 **插头图标（API 连接）**，选择 **聊天补全 → 自定义（OpenAI 兼容）**，在“可用模型”后面点击 **API 账户管理** 卡片展开。

仓库根目录已包含扩展清单和运行文件，无需下载 ZIP、编译或手动复制文件。后续可在酒馆的扩展管理中检查更新。

### 手动安装

如果不使用安装器，将本仓库文件夹复制到当前用户的扩展目录（1.14.0 默认是 `data/<用户>/extensions/`）：

```text
SillyTavern/data/default-user/extensions/sillytavern-api-manager/
```

多用户部署时把 `default-user` 换成实际用户目录名。管理员要安装为所有用户时，才使用酒馆的全局第三方扩展目录 `public/scripts/extensions/third-party/`。目录中应至少包含 `manifest.json`、`index.js`、`balance.js`、`settings.html` 和 `style.css`。然后重启酒馆。

## 使用

1. 打开顶部 **插头图标 → 聊天补全 → 自定义（OpenAI 兼容）**，点击“可用模型”后面的 **API 账户管理** 卡片展开。在“添加 API”中同时填写账户名称和分组。分组可选，也可以从已有分组中选择。
2. 直接填写 API 基础地址和 Key，点击“获取模型”并选择默认模型，然后点击“保存 API”。
3. 已保存的账户按组显示；点击某一组的标题即可展开或收起该组，其他组保持原来的状态。未填写分组的账户放在“未分组”中。
4. 点击账户旁的“刷新余额”，结果直接显示在该账户旁。编辑账户时也能在表单内查询，查询不会清空尚未保存的名称或分组。
5. 点击“应用”会填入酒馆的 **聊天补全 → 自定义（OpenAI 兼容）** 地址、Key 和模型，并自动触发原生“连接”。连接结果以酒馆的连接状态为准。

卡片默认收起，再次点击标题栏即可收起内容。展开和收起不会清空正在填写的表单。

从旧版本更新后，请刷新页面，在“可用模型”后面找到卡片。已有账户、Key 和分组会保留。

## 余额接口说明

扩展根据 API 地址自动查询已适配的官方接口和常见中转站接口，并按接口含义显示“余额”“可用额度”或“密钥额度”。New API 的原始额度会在有可靠站点单位配置时换算；拿不到单位配置时显示原始额度单位。密钥不限额时会明确标注，服务商是否公开账户余额取决于其接口。

余额查询是扩展自带的通用功能，不依赖作者的账户、服务器或固定中转站地址。已适配 DeepSeek、OpenRouter、硅基流动、Moonshot 官方接口，以及使用令牌额度或兼容账单协议的 New API / One API 站点。不同站点可能只允许查询密钥额度；OpenAI 官方普通 API Key 没有账户余额接口。

### 首次使用时的代理配置

允许浏览器跨域请求的站点可以直接查询。遇到跨域或网络限制时，扩展会自动尝试**当前酒馆服务器**的原生 CORS 代理，不使用作者的服务器或额外的第三方中转。纯前端扩展不能自行修改酒馆服务器配置，因此每位使用者如果看到“酒馆代理尚未开启”，需要在自己的酒馆执行一次以下操作：

1. 打开正在运行的酒馆所使用的 `config.yaml`，找到并修改这一项（不要重复添加）：

   ```yaml
   enableCorsProxy: true
   ```

2. 保存配置并重启酒馆，然后回到账户卡片点击“刷新余额”。

普通部署使用酒馆目录下的 `config.yaml`。Docker 部署使用挂载到容器 `/home/node/app/config` 的宿主机目录里的 `config.yaml`；应编辑持久化挂载目录中的文件。

**1Panel：**在“容器”中打开酒馆容器详情，找到 `/home/node/app/config` 对应的宿主机路径，再通过“系统 → 文件”打开该路径中的 `config.yaml`，修改后重启这个酒馆容器。不同人的安装目录可能不同，应以自己容器的挂载路径为准。

代理开启后，扩展仍会区分密钥错误、接口未开放和网络失败，不把查询失败显示为余额为零。

## 安全与隐私

Key 会随 SillyTavern 的扩展设置保存在本机浏览器/服务器设置中，并会直接发送到你填写的服务商接口。扩展不会把 Key 写入日志、账户列表或 GitHub；请不要把包含个人设置文件的目录提交到仓库，也不要把 Key 写进预设或源码。删除账户会同时删除本地保存的 Key。

## 兼容性

- 目标版本：SillyTavern 1.14.0 及相近 1.14.x 版本。
- 模型获取协议：OpenAI 兼容 `GET <baseUrl>/models`，响应支持 `{ data: [{ id }] }`、`{ models: [...] }` 等常见格式。
- “应用”按钮使用酒馆 1.14.x 的原生自定义聊天补全控件；余额查询和分组编辑不打开新窗口或独立页面。

## 开发

这是无构建依赖的 ES module 扩展。修改后把仓库目录放回 `public/scripts/extensions/third-party/`，刷新页面即可验证。提交前建议运行：

```bash
node --check index.js
node --check balance.js
```
